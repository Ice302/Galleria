# Galleria

A scroll-driven landing page and exhibition for landscape posters. An F1 car dissolves into ~18,000 pixels that re-form as a cruise ship. It ends in a split-flap departures board, a pinned full-screen "reel" of every poster, and a contact sheet.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
```

## Put your posters in

1. Drop your original files (jpg, png, webp, tiff, avif) into `posters-src/`.
2. Run:
   ```bash
   npm run posters
   ```
   For each file this writes 800 / 1600 / 2400 px WebP copies to `public/posters/`. It also strips all EXIF/GPS metadata and records each poster's dimensions and dominant colour in `content/posters.json`. The placeholder entries are replaced.
3. Open `content/posters.json` and fill in `title`, `year`, `medium`, `size`, `description` and `alt` for each poster. Re-running `npm run posters` keeps your edits.

### Landscape and portrait

The importer sorts posters by shape. Landscape works go to **Hall A**, the horizontal reel, and portrait works go to **Hall B**, the portrait slider. To override where a poster goes, set `"format": "portrait"` or `"landscape"` on it in `posters.json`.

Hall B steps one poster per scroll gesture and always stops on a poster, never mid-transition. Touch and keyboard scrolling finish the transition in the direction you were going.

Hall B needs a few slides to slide between, so it's filled with on-brand placeholders until you have four portrait posters. Each portrait poster you add replaces one placeholder. Placeholders only ever appear in Hall B, never on the board, the wall or the contact sheet.

### Message, quote and signature

The "Message from the artist" section and the quote on the wall come from `content/site.json`:

```json
"message": { "label": "Message from the artist", "lines": ["Every poster starts as a feeling", "I could never put into words"], "image": null },
"quote": "I don’t make posters of *what* happened. I make posters of *how* it felt."
```

- **Image:** set `image` to a photo of you, for example `"/me.jpg"` placed in `public/`. Until you do, a placeholder portrait shows where it goes.
- **Emphasis:** wrap words in `*stars*` to emphasise them in the quote.
- **Signature:** by default it's your `artist` name set in the Hurricane signature typeface. When the site builds, each letter's centre line is traced, so on screen the signature is inked stroke by stroke as you scroll.
  - Set `"signatureFont"` to `hurricane`, `herr-von-muellerhoff`, `mrs-saint-delafield`, `corinthia` or `allison` to change the style.
  - To use your real signature, save it as `content/signature.svg`. Only its stroke paths are used, so draw it as lines, not filled shapes.

### The "Galleria print" treatment

Your posters have very different palettes, so the importer gives them all one shared print finish. It does this by pulling shadows toward ink and highlights toward bone paper, then adding a 45° halftone screen, fine grain and a soft vignette. The artwork itself isn't repainted.

Your files are never modified. Each poster is published twice:

- **The print version**, shown on the site.
- **The untouched original**, revealed by the hover loupe in the reel and by the "View original" toggle (or the `O` key) in the viewer.

You can tune or switch off the treatment in `content/site.json`, then re-run `npm run posters`:

```json
"posterPrint": { "enabled": true, "tone": 0.32, "halftone": 0.55, "grain": 0.2, "vignette": 0.5 }
```

`tone` controls how strongly colours pull toward the palette. Use 0 to keep your colours and about 0.5 for a near-duotone look. The other three values control texture.

Optional fields per poster:

- `tone` sets the reel background while that work is on screen. Use one of `ink`, `orange`, `bone`, `graphite` or `sage`.
- `status` replaces the departures-board status, e.g. `"Sold out"`.

Order in the file = order on the site. `posters-src/` is git-ignored, so originals never get published. Once your own posters are in, you can delete the `public/posters/placeholder-*.svg` files.

## The 3D models

The F1 car and cruise ship are Sketchfab models, both licensed CC BY 4.0 and credited in the site footer and in `public/models/CREDITS.txt`.

- **Originals** live in `models-src/`. That folder is git-ignored and never published.
- **Web versions** are generated by `npm run models` (`scripts/prepare-models.mjs`) and saved as `public/models/f1.glb` and `ship.glb`, about 1.5 MB together.
- **What the conversion does:** it simplifies both models and removes sponsor decals, passenger figures and other unneeded parts. It repaints the car's livery into the palette, with "GALLERIA" replacing the script logo.
- **Colours and shading** are applied in the browser by `src/three/models.js`, by material role (livery, carbon, tyre, hull, deck, glass, lifeboats…).
- **Fallback:** if the models fail to load, the original code-built car and ship are used instead.

To use different models, put them in `models-src/` and update the file names and part rules in `scripts/prepare-models.mjs` and `src/three/models.js`.

## Your details

Edit `content/site.json`: name, role, email, location, socials, and `url`. Set `url` to your real domain before deploying, because it is used for the canonical link, Open Graph and JSON-LD. The page reloads automatically when you save either content file.

## Build & deploy

```bash
npm run build      # → dist/
npm run preview    # serve the production build locally
```

`dist/` is a static site that can be hosted anywhere. Security headers are included:

- **Netlify / Cloudflare Pages**: `public/_headers` is copied into the build.
- **Vercel**: `vercel.json`.
- Other hosts: production builds already carry a strict Content-Security-Policy `<meta>` tag. Add the headers from `_headers` if your host allows it.

If you later host images on a CDN, `img-src` already allows `https:`. Anything else external (analytics, embeds) needs to be added to the CSP in `build/content.js`, `public/_headers` and `vercel.json`.

## Check it

```bash
node scripts/snapshot.mjs http://localhost:5173/ snapshots
```

This screenshots every chapter at desktop and phone sizes with your installed Chrome, and prints any console or CSP errors.

## How it's put together

```
content/            site.json + posters.json — the only files you need to edit
build/content.js    Vite plugin: renders the gallery into index.html at build time (escaped, validated)
src/three/          the 3D story
  stage.js          renderer, camera keyframes, adaptive quality, render loop
  models.js         loads + restyles the imported car and ship
  f1.js, ship.js    code-built fallback models (loft.js sculpts the bodies)
  morph.js          surface-sampled particle morph between the two models
  materials.js      toon shading + dissolve / window / band shader patches
  environment.js    track, speed lines, contour-line ocean, sun
src/ui/             story HUD, exhibition reel + board, lightbox, extras
src/styles/         tokens and layout
scripts/            poster import, model preparation, placeholder generator, snapshot tool
models-src/         original downloaded 3D models (git-ignored)
BLUEPRINT.md        the 100-point plan this was built against
```

The story runs in "chapter units": 0 hero, 1 velocity, 2 transit, 3 scale, 4 boarding. Camera keyframes live at the top of `src/three/stage.js`. Speed and morph timing are in `src/core/story-data.js`. Colours are CSS variables at the top of `src/styles/base.css`, with the 3D palette in `src/three/materials.js`.

## Accessibility & safety, in short

- Reduced motion is respected throughout.
- The page works without JavaScript and without WebGL.
- The viewer is keyboard-first: ←/→ to browse, Esc to close, click to zoom.
- No trackers, cookies or third-party requests.
- The production CSP allows no inline scripts or styles.

More detail is in `BLUEPRINT.md`.
